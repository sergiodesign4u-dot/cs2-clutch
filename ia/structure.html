The global sweep

Step 3, 12 August 2026. What else in this product is global, answered by counting consumers rather than by naming components.

The two tests, and the one thing that decided every row

A candidate is global when it appears on many pages, or when it is a shared structure or dataset that several pages consume. Everything else is specified inside the single node that uses it. For every candidate the list of consuming nodes was written down before the verdict rather than after: a candidate with one consumer is not global however large it is, and a candidate with five is global even when it renders nothing at all.

Four nodes came out of it and not one is a new surface. Round 1 is still the nine surfaces D-20 locked. Three of the four render nothing: they are structures the nine already read, described once instead of nine times.

One new node type, named rather than smuggled in

register: a node holding a structure or a dataset read by several nodes, described once and drawn by none. Not a page, because nobody navigates to it. Not a component, because nothing renders it. Calling it either would misfile it in the hub above and, worse, would enter it into stage 04's coverage check as a screen with no wireframe. Registers are not wireframed at stage 04. The nodes that read them are.

What the sweep found, and it found it in our own week-old prose

Node 0.2 claimed a capability that does not exist. Its statistics verdict said cases opened "becomes checkable by reconciling with the published round ledger on 1.2". There is no published round ledger. The backlog uses the word ledger four times and every one is the internal settlement ledger; node 1.2 holds a verifier and a round input and publishes no rounds in bulk.

The rule that catches it was already written. A block with no parent in the three legal classes is cut, or carried with its orphan status printed. What was missing was pointing that rule at a sentence written one step earlier, which is the same failure mode as the base layer's count drift: the instrument existed, nobody aimed it at the new prose.

Corrected, not deleted. The route that does exist is the observed rate counter, row D3, whose N comes from the same settlement ledger that pays users. It reconciles per case rather than as one auditable total, and it is conditional on D-B, whether six years of roll history can migrate and be published at all. If D-B fails, cases opened loses its route and the slot goes to a number that has one. A browsable public round ledger would be a new backlog row and is not one today. Both sit in the open items of 0.11.

Block bank by type

Step 4, 12 August 2026. Where the composition of a page comes from, fixed before the pages are written. Source: ia/docs/blocks.md.

The hole this closes

Every other artefact in this pipeline has a rule of origin: a research fact carries a cited source, a CJM emotion comes from mining or is [?], a To-Be capability traces to a barrier. The block composition of a page had none. The node template says "content blocks: 1, 2, 3" and does not say where they come from, and a model that is not asked for a source returns the median of everything it has seen: hero, filter, cards, pagination. Twenty six file-level nodes are eight types, so the pass runs once per type rather than once per node.

Two sources on two different questions. Competitors through Playwright answer what actually holds a person inside our category, public and pre-login only. Four gaps, named before the tables rather than after

T4 has no competitor screens at all. Deposit, withdrawal and identity verification are behind login on all five hard competitors, and this project never logs in. The substitute is public documentation of the same mechanics, and it turned out to carry the domain rules in plain words. CSGORoll refused this environment with HTTP 403 for the second time today. Refero holds no live-event detail page: no auction, no draw, no page whose centre is an outcome happening now, so the reveal has no external craft reference and this bank says so instead of inventing one. And T8 was cut to a reduced pass on purpose, one competitor instead of two, because it is a single node and the 404 is the most settled composition in the craft.

The gap the barriers predicted, found on a live page

Neither competitor shows chance and current value on the same item. Hellcase publishes the full drop table pre-login, chance per item to three decimals, from 0.207% to 13.386%, and puts value only in "last 7 days top drop". skin.club shows value in "last top skins" and hides odds behind a [ CHECK ODDS RANGE ] control with the stamp "updated 11 minutes ago". That is exactly what row D2 asks for and no competitor closes it. A chance with no value is a lottery ticket with no prize printed on it; a value with no chance is a shop window.

And three numbers appear on no case page in the category at the moment of spending: published tested RTP, expected value at this entry cost, and the observed rate against the published one. D-14 says the brand is that our own numbers are checkable. This is where that becomes markup.

The single most telling block in the bank

Hellcase's case screen prints its keyboard shortcuts on the controls: GET to ENTER, QUICK STOP to SPACE, SELL to S, REPEAT to R. One key liquidates what you won and one key spends again, offered as a convenience beside a multi-open selector of 1, 2, 3, 4, 5 and 10. Nothing in this bank required less argument to reject, and nothing states the difference between the two products more plainly.

A second one is a proof that proves nothing. Key-Drop's safety portal, the only responsible-play surface any of the five publishes, carries a decorative verifier widget with a fabricated server seed, a fabricated client seed and the line "Outcome Verified: DRAGON LORE (FN)" for a round that never happened. Node 0.14 forbids a verified badge in any variant, written before this page was opened. Here is the live instance of why.

The rarity ladder, walked, and one claim deliberately not made

Owed by this stage before step 5, because 0.6 cannot be specified without it. Walked by reading the computed background colour of every rarity chip on two Hellcase case pages: seven distinct tiers, #b0c3d9, #5e98d9, #4b69ff, #8847ff, #d32ce6, #eb4b4b, and #f7b62d which appears only on the case that contains knives and gloves.

The claim not made: six of these look like the CS2 client's own palette, which would mean the ladder is the game's rather than any platform's and that we may not restyle it freely. That reading is model memory and stays [?] until a Valve or Steam page is opened and the values are compared. What is usable without that check: 0.6 needs a rarity slot with seven values, and rarity, wear and StatTrak are three axes rather than one.

What the bank changed in nodes already written

Three, recorded rather than silently applied. 0.8 gains a pause control, because Key-Drop's ticker has one and ours did not, and it doubles as the reduced-motion answer. 0.6 gains a third field, since rarity, wear and StatTrak are separate axes. And 5.1 or 5.3 may need a holding deadline: Hellcase converts an unwithdrawn item to balance after thirty days, a real product rule that lives in an FAQ, and if we carry one then G5 requires it stated before entry.

Two carriers were built before this bank existed, 0.1 and 0.2, because the pack orders the steps that way. If the bank shows a block those carriers lack, that is a finding for the step 8 audit, not a quiet edit.

What changed is that the specifications now hold more states than the map numbers. Writing cluster 2 needed eight internal states the map does not carry a number for: the market lookup, detection unavailable and declined on 2.1, returning from Steam, cancelled at Steam and already signed in on 2.4, and session expired and market refused on the document on 2.7. Each was printed with its parent and with the map's own not-a-node test applied, which is why none of them became a numbered node.

The distinction is load bearing for stage 04. A numbered state is a thing the map routes to and the coverage check counts. An internal state is a condition inside one screen that the wireframe must still draw. Merging the two counts would either inflate the map or hide eight screens' worth of work. The closed form lives on its own page

Detail layer critique. Before and after by class, five telling pairs, every withdrawn finding with the reason it did not survive, and the split between what Codex caught and what only a browser could.

The headline pair: every node page links home as structure.html#<node> and this hub gave its chips no id at all, so twenty three backlinks resolved to nothing. No author could have found it, because each one's own page was correct. The defect lived between twenty three files and one renderer.

How a node is specified

The same template on every one, so that thirty specifications read as one document rather than as thirty opinions.

What every node carries

Purpose in one line and the jobs it serves. URL and slug, breadcrumbs. Content blocks in mobile-first priority order, taken from the block bank rather than from anywhere else. Components used, with variants. States in full. Filters and facets where the node is a listing. One main call to action. The emotional support mechanism, where the base layer's table puts one on this node. Responsive notes, mobile stack into desktop. Then the SEO block, A to E.

The SEO block, A to E, on every indexed node

A. Meta tags with finished copy: title, description, canonical, robots, OG. B. Exactly one H1 plus the H2 list in block order. C. Finished SEO text, not a placeholder. This block stays the node's property to the end of the pipeline: stage 05 aligns it to voice and syncs the final version back here. D. Schema.org type. E. The optimisation checklist. Private and transactional nodes carry noindex and no schema instead: sign in, identity, deposit, account, withdrawal.

Two rules that decide what a node may contain

A block with no parent does not exist. Every block traces to a job in jtbd.md, a barrier in cjm-as-is.md, or a named SEO requirement. Nothing gets in because it is usual.

Mockups stay black and white through this whole stage. Colour, brand and imagery arrive at stage 06. The colour on this documentation page is the site theme and a different thing entirely.

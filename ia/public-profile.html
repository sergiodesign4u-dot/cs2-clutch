Amended 24 August 2026 by D-93. The page can be switched off, and it is on by default

Founder decision, 24 August 2026. A person can hide their public profile. The default is visible.

Why the node needed this and did not have it. D-90 published a page carrying a person's name and everything they have won, and gave them no way to take it down. That is the one shape of this node nobody argued for. 0.8 wanted the destination, 7.1 refused a trophy shelf outright, and neither of them wanted a permanent one.

Default visible, and the default is the decision rather than an absence of one. Off by default would switch off something the product already does, and would empty 0.8's destination, this node and the route from 5.10 at once.

And two things it does not change, printed on the page rather than only here. The public page of a round already shared stays up: 7.1 is about the round, its address was given out by the person who shared it, and retracting it is a different capability with a different owner. The name still appears in the live drop strip. A switch trusted for more than it does is worse than no switch, so both exclusions render on the hidden state and on the settings row itself.

A stranger is never told that a page is hidden. They get player-gone.html, the same page an account that never existed gets. A "this person hid their profile" screen publishes the very fact the setting exists to withhold, and it tells a stranger that the address is worth trying again later. The two causes are indistinguishable from outside, which is what makes the switch worth anything.

The strip carries no hidden badge either, for the same reason and one more: a badge would mark out which accounts have something worth looking at.

Nothing on player-gone.html changes for this. Its copy already says what is true of both causes and does not speculate about which. That restraint was the right call before it had a second cause and is load bearing now that it has one.

The hidden state shows the page, not a stub. What a person needs in order to decide whether to turn this back on is the thing itself, not a description of it. A hidden state that showed a stub would make the switch a guess, which is the same argument D-89 made for 5.10's "See yourself as a stranger does".

The control is not on this page. It lives once, on 5.11 under Security, and this page routes to it. One setting, one control, D-58.

And it was accurate about the object. baseline.md section 9.9, the founder's capture of 21 August 2026: the live product's profile is an inventory history with four tabs, every item that account has won, priced, and nothing on it a reader can check. That is a trophy shelf and this node builds one.

What answers it, and it is the only reason this build is defensible

Every trophy on the shelf carries a route to its own round proof. Design principle 1 applied to the one surface built against a node's advice: the shelf exists, and nothing on it is a claim rather than a record. A stranger can recompute any line.

And there is no total. No sum, no rank, no tier, no position against anyone. D-25 rule 3 says a tier gives a case and nothing else. A shelf with a total at the top is a leaderboard with one row.

Parent class: none, and the cell is printed rather than filled

Not a barrier from the As-Is map, not a job in jtbd.md, not a compliance constraint or a design principle. The founder asked for it directly, which is the same ground D-36 put 5.10 and 5.11 on, and the treatment is D-38's: the capability ships with the empty parent shown and no backlog row is retro-fitted into cjm-to-be.md.

One thing it does close, and it is a routing debt rather than a parent. D-59 gave the live feed's avatar a public profile as its destination and printed "public profile: no node yet" on every tile of every page for two days. That mark is now off, because its subject is fixed. A mark left standing after its subject is fixed is the next false statement.

Four things the baseline's profile does that this node refuses

Each one is a rule this product already holds, applied to the surface that most wants to break it.

One counter, not three

The capture's banner reads Cases, Case battles and Gunfights, and two of the three read N/A. Two modes that do not exist, rendered as empty figures, is the dead item defect with a number in it. Round 1 has one mode, so the banner carries one count and names the absence in words. When a second mode arrives it brings its own count and its own list.

No history tabs

For the same reason and by the same rule as Home's four game mode cards, D-19: one live tab of four is the defect, so the carrier is not drawn until it has more than one live item in it.

The name is not printed twice

The baseline repeats it under the avatar. Two renderings of one fact is the defect class this project has now caught four times, and this page is the one whose whole subject is a person's name.

The public id is not the account id

The id on 5.10 is what support and an appeal refer to; publishing it hands a stranger the string an impersonation uses. The public id is a different value and its format is [?]. The node's recommendation is that it is opaque: the live product's is a six digit number a reader can decrement, which makes the registered account total readable from outside. Same class of leak 7.1 flags for the round id, and the same recommendation.

What the shelf lists, and it is not the inventory

It lists what the account has won, not what it holds

An item sent to Steam or sold back for coins leaves the account and stays on this page, because what happened happened. A shelf that empties when a person cashes out is a shelf reporting current wealth, which is a different and worse object than a record of outcomes.

The item card is 0.6 with a stranger's field set

No tick, no actions, no market foot: a stranger owns nothing here and may act on nothing here. What is added is the case it came from, the date, and the route to the round.

The value shown is the value at the time it is read, in coins, and what one coin is worth in real money is not published, D-28. This node does not print a value at the moment of the win: row F2 was removed from the item card by D-90 and this node does not reintroduce it on a public surface.

Indexation, and it is decided here rather than inherited

URL /u/<public-id>. Indexed no, noindex, follow. Canonical self. Schema none. Breadcrumb none.

noindex, and the reason is not 7.1's reason

7.1 is noindex because indexing one object is pointless. This page is noindex because it is about a person. Letting a crawler hold a list of what someone owns is a publication decision nobody has made, and the owner cannot turn this page off yet, so the least the product does is not hand it to a search engine.

There is no directory and no search

The page is reached from a drop in the live strip or from a shared result. The shelf exists and is not enumerable, which is a real limit on the harm and is why the recommendation about the id format matters: an opaque id keeps it that way, a sequential one does not.

What this cost, stated

A trophy shelf now exists in a product that spent a node arguing against one.

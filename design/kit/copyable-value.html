Copyable value

A key over a value read one character at a time, and Copy; once copied, a green line says so. It stands as a block, as a one-line strip under the open act, and as a wallet address with its QR. Everything on this page is drawn by design/system/components/copyable-value.css through index.css, the same file a screen will load.

Variants and sizes

One form, two axes. Content decides which parts stand, never how a part looks; ground decides which roles the key and the answer read. The QR's size is read from the rendered sample, not from the stylesheet.

  • Block. Key, value and Copy stacked: a ticket or reference id, a seed or hash the person reads whole.
  • Inline (--inline). The one-line strip under the open act: key and value on one centred line, no Copy. It stands under the case screen's open act as the server seed hash.
  • Address (--address). A wallet address with its QR: the QR beside the address from 600px up, over it under 600px. Narrow the window to see it stack.
  • Ground, on a plate (--on-plate). The theme's ground is the default: in the light theme the key turns to dark ink. A plate that keeps its colour in both themes (the Proof block's dark hash well on the fair blue, round 3b) wears .copy-value--on-plate: the key, the value's chip and the answer keep the dark theme's look in light (D-266). The Copy Button beside it keeps the Button's own look, which turns light in the light theme: read again at step 7.

When to use

A value that a person must carry somewhere else, exactly, is shown whole and copied with one press: the server seed hash published before a round, a reference to quote to support, a wallet address to pay to. The hash is the proof, so it wraps and never cuts (design principle 1, trust is the product). Copy says what happened in a line beside it: "Copied", or what to do when the browser refused. The key says what the value is in the voice's own word, "Server seed hash" (microcopy G159), "Your deposit address".

Rule and anti-rule

Use it

The crypto deposit address with its QR and Copy; the reference of a refused sign in; the server seed hash under the open act.

Take another component

A value read, not carried away, is a Key-value line or a Figure. A matched or mismatched round is a Badge. A link to somewhere is a Text link. A full check of a round, with its fields and verdict, is the Verify form, an organism that holds this molecule.

States

No states: it is not interactive. The block has no hover, press or focus of its own; Copy is a Button and keeps the Button's states (the Button's page), so no snapshot is repeated here. What changes is the line beside Copy, and a script writes it.

In the code

TokenKindDarkLight

Read live from tokens.css. The well reads the tile's veil and edge; the answer reads --text-match, the role for a copy done; the QR tile is white in both themes (--bg-mark-on-plate) with dark ink (--text-on-accent), because a code is read dark on white. On a plate the key reads --text-body-on-plate, the chip --copy-value-bg-on-plate, --line-edge-on-plate and --text-on-plate, and the answer --text-match-on-plate, the last rows, the same in both themes. Geometry and type come straight from the primitives, the monospace face included. One component token, --copy-value-bg-on-plate, the chip's veil on a plate (D-266); no colour primitive is read directly.

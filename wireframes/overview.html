Inline CSS is transport, not a home, and this is where the stage breaks quietly

At step 8 parallel subagents write screens and cannot all write into _wf.css. So an agent puts its screen's rules inline, and the reconcile pass of the same step folds them back. Two criteria decide every rule:

1. A token value never lives inline. Not even on one screen. Screens write var(--wf-...). A literal inline is where drift starts. 2. A rule on two or more screens moves into _wf.css, the same "two or more occurrences" test stage 07 uses to decide what is a component.

Why this is not pedantry. Stage 07 extracts the component kit from these screens. If the structure of twenty screens lives in twenty inline blocks, the extract honestly collects a kit made of the differences: three versions of one card, two grids, four spacings where there should be one. The defect becomes visible three stages after it was created.

Hover, and the bug that separating it fixed

The reference opens on hover. Hover alone excludes touch entirely and the keyboard almost entirely, so the control opens on hover, on click and on Enter or Space, and closes on Escape, on a click outside and when focus leaves.

Bound as two JS handlers writing the same flag, the control appeared dead to a mouse: hover opened the menu and the click that followed toggled it straight back to closed. Hover is a pointer affordance with no state behind it. CSS shows the panel and records nothing, inside a (hover: hover) query so a touch device never inherits a rule it can only fire with the tap it already spent. Click and keyboard set the class, and that class is the only thing aria-expanded reports, because hover is not a state a screen reader has.
